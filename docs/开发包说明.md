# 组员开发包说明

这是 `Cloud-Shadow 组员演示开发包` 的 **Web 复刻工程**（路线 B），可以直接下发做新功能开发。
本文件只讲「怎么跑起来、怎么加功能」，架构决策与契约细节见根目录 [README.md](../README.md) 和 [CONVENTIONS.md](../CONVENTIONS.md)。

---

## 1. 包里有什么 / 没有什么

**有**：前端源码（8 个复刻页面 + 8 个组件）、只读 shim（7 个端点 + 健康检查）、legacy 建库脚本、验收脚本、文档、启动脚本、皮影角色/砌末/过场配乐（`public/piying`）、CV 运行时（`public/cv/vendor`，摄像头玩法开箱可用）。

**没有（必须在你自己机器上准备）**：

| 缺什么 | 为什么不在包里 | 怎么补 |
| --- | --- | --- |
| `node_modules` | 平台相关、体积大 | `npm install`（根目录 + `server/` 各一次） |
| `.env.local` | **含明文数据库口令，绝不随包分发** | 复制 `.env.example` 为 `.env.local` 后填口令 |
| 素材（603 MB / 410 文件） | 体积过大，进 git 会让仓库膨胀到 GB 级 | 运行 `scripts\extract-assets.ps1` 一键抽取，见第 4 节 |
| MySQL 数据 | 库里是本地数据 | 导入 `server/db/10_legacy_v1.sql` |

---

## 2. 环境要求

- **Node.js ≥ 18**（实测 24.19；用到原生 `fetch`、`AbortController`）
- **MySQL 8**，本地 `127.0.0.1:3306` 可连
- **浏览器**：Chrome 或 Edge（只有跑验收脚本需要；脚本会自己探测常见安装路径，探不到就设 `CHROME_PATH`）
- **素材**：工程内 `assets/images` 需有 603 MB / 410 个文件（首次运行 `scripts\extract-assets.ps1` 补齐）
- Windows 用 `.bat` 启动脚本；macOS/Linux 按第 4 节手动起两个进程

## 3. 五步跑起来

### 第 1 步：装依赖

```powershell
cd <包根目录>
npm install
cd server
npm install
cd ..
```

### 第 2 步：建库并导入数据

用有建库权限的账号建一个库（名字随意，下文用 `deepseek`），然后导入：

```powershell
mysql -h 127.0.0.1 -P 3306 -u <用户> -p -D deepseek --default-character-set=utf8mb4 -e "source server/db/10_legacy_v1.sql"
```

> 该脚本是 `cloud_shadow_v2_full.sql` 的 **legacy 段派生版**：已去掉 `CREATE DATABASE`、改为 `USE deepseek`。
> 导入后应有 **26 张表 + 3 个视图**（`provinces` / `schools` / `shadow_region_info`）。用下面这条核对行数，
> **不要**用 `information_schema.tables.table_rows`（InnoDB 估算值会给出离谱数字）：

```sql
SELECT 'quiz' t, COUNT(*) FROM quiz_questions
UNION ALL SELECT 'daily', COUNT(*) FROM daily_appreciation
UNION ALL SELECT 'interactive', COUNT(*) FROM interactive_characters
UNION ALL SELECT 'craft', COUNT(*) FROM shadow_craft_process
UNION ALL SELECT 'timeline', COUNT(*) FROM shadow_history_timeline
UNION ALL SELECT 'common_img', COUNT(*) FROM app_common_image
UNION ALL SELECT 'regions', COUNT(*) FROM regions;
```

期望：`116 / 72 / 72 / 8 / 8 / 87 / 34`。

### 第 3 步：配置 `.env.local`

```powershell
Copy-Item .env.example .env.local
notepad .env.local
```

必填：`DB_USER`、`DB_PASSWORD`、`DB_NAME`；
按需改：`SHIM_PORT`、`WEB_PORT`。`ASSET_ROOT` 一般不用填——工程内 `assets/images` 存在时优先级最高。

> 口令只能出现在 `.env.local` 或进程环境变量里，**不要**加 `VITE_` 前缀（那会打进浏览器包），`publish`/`zip` 时也绝不能带上这个文件。

### 第 4 步：起两个进程

```powershell
npm run shim     # 终端 1：http://127.0.0.1:8787
npm run dev      # 终端 2：http://127.0.0.1:5173
```

Windows 也可以直接双击 `启动本地演示.bat`（自动开两个窗口并打开浏览器）。
macOS/Linux 等价命令同上，`npm run` 全平台通用。

### 第 5 步：确认通了

```powershell
npm run verify:shim    # 19 项契约，应全 PASS
npm run verify:web     # 8 路由 × 2 视口，应 16 项全 PASS
```

`verify:web` 会把截图写到 `.artifacts/screens/`、报告写到 `.artifacts/verify-web.json`。

## 4. 素材怎么准备

素材（603 MB / 410 文件）物理放在**工程内** `assets/images`，`/images/**` 直接映射它，
所以工程是自包含的；但该目录**刻意不进 git**（会让仓库膨胀到 GB 级），因此每个拿到仓库的人都要补一次。

二选一：

**方式 1：一条命令补齐（推荐）**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\extract-assets.ps1
```

脚本会自动选择源：

| 情况 | 行为 |
| --- | --- |
| 默认（同级目录 `..\PiYingGameWeChat\storage\assets\legacy-import\images` 存在） | 用 robocopy 直接复制，最快 |
| 显式传 `-ZipPath <任意zip路径>` | 从 zip 里只抽 `storage/assets/legacy-import/images/**` |
| 显式传 `-SourceDir <任意图片目录>` | 从指定目录复制 |

三个路径参数都支持相对写法（相对工程根解析），默认值就是相对路径，不再依赖绝对路径。

两种模式都实测过：410 个文件 / 603 MB，0 失败。

**方式 2：手动复制**

把源工程 `storage\assets\legacy-import\images` 的内容整体拷到工程内 `assets\images`，
保持 `art/`、`index/`、`map/` 等子目录结构不变。

> 工程内存在 `assets/images` 时**不需要配置任何变量**。
> 只有把素材放到工程外，才在 `.env.local` 里用 `ASSET_ROOT` 覆盖（工程内存在时优先级更高）。
> 若素材缺失，`npm run dev` 启动时会打印明确告警，而不是静默无图。
> 已做两处只读兼容，**不需要你改名或改库**：
> 1. 数据库里河南省的图写的是 `map/hnpy(1).png`，磁盘是 `hnpy (1).png`（带空格）—— 解析层会按「去空白 + 忽略大小写」找到真实文件；
> 2. 同一组素材存在 `.PNG` / `.png` 混用，解析层使用磁盘真实文件名，因此在大小写敏感的 Linux 上也能命中。

```
  store/imageStore.js   /assets/common 的 imageKey→URL 表 + normalizeImageUrl（图片路径统一过它）
  config/artAssets.js   art-v2 素材表（9 组 getter）。新增素材在这里加 getter
  utils/                navigation（地区 localStorage）、rpx（内联样式换算）、toast
  styles/base.css       --rpx 基准、reset、宽屏辅助类
  components/art-v2/    页面外壳 / 顶栏 / 底栏 / 按钮 / 状态
  pages/                8 个页面
server/
  src/index.js          HTTP 入口与路由表
  src/endpoints.js      7 个端点的 SQL 与字段映射（camelCase 规则都在这里）
  src/db.js             连接池 + 只读纪律（拒绝非 SELECT）
  src/env.js            .env.local 加载与校验
  src/assets.js         素材文件解析（含上面说的两处兼容）

```

## 6. 怎么加一个新页面

1. 新建 `src/pages/FooPage.vue`，照着 `ProcessPage.vue` 的结构写（外壳 + 顶栏 + 状态 + 内容）；
2. 在 `src/router/index.js` 的 `routes` 里加一条（`meta.title` 决定标签页标题）；
3. 若要出现在底部导航，改 `src/config/artAssets.js` 的 `artNavTabs`（注意它是 5 个 tab 的设计）；
4. 在 `scripts/verify-web.mjs` 的 `ROUTES` 里加一条 `{ name, path, expect, forbid }`，跑 `node scripts/verify-web.mjs foo` 自检。

**样式约定**：`rpx` 原样写（构建期 PostCSS 自动转 `calc(N * var(--rpx))`）；内联样式用 `rpx(220)`；不要引 UI 框架，art-v2 是自绘的。

---

## 7. 怎么加一个新接口

1. 在 `server/src/endpoints.js` 写一个 `async (pool, limit) => data` 的查询函数，**必须用 `select()`**（它会拒绝非 SELECT 语句）；
2. 在 `server/src/index.js` 的 `ROUTES` 里注册路径；
3. 前端用 `await request({ url: '/foo' })` 调用，返回值**已解包**（等价于源码 `unwrapResponse` 之后）。
4. 在 `server/scripts/verify-shim.mjs` 补一条断言，跑 `npm run verify:shim`。

两个必须遵守的口径：

- **返回 v1 envelope**：`{ code: 200, message: 'ok', data }`，业务失败用 `code: 500` + `data: null`，HTTP 状态恒为 200；
- **字段命名按前端 `normalize*` 的容忍度定**：本项目里 `/assets/common`、`/quiz/questions/random`、`/regions/by-name`、`/craft-process/steps` 只认 camelCase，`/history/timeline` 保留 snake。新接口建议统一 `toCamel`（`server/src/envelope.js`）。

> `shim` 定位是「只读 legacy 兼容层」。新功能若要写数据，**不要**在这里开写接口——那是 v2 后端该做的事。

## 8. 验收与提交前自检

```powershell
npm run build          # 必须能过（约 1 秒）
npm run verify         # shim 19 项 + 浏览器 16 项
```

提交前额外确认：

- 没有把 `.env.local`、`node_modules/`、`dist/`、`.artifacts/` 提交进去；
- 新增页面在 375 px 与 1440 px 下都没有横向溢出（`verify:web` 会查这一项）；
- 没有引入新的运行时依赖（真要引，先和大家对一下）。

## 9. 已知限制（不是 bug，别当成任务）

- 素材权利状态是 `internal`，本项目处于 `internal_preview` 里程碑：**产物不得对外发布**。
- shim 只读、无鉴权，仅限本机/内网演示。
- `plays` / `inheritors` / `exhibitions` 是空表，别依赖。
- 地图页 `河北` 与 `山西` 的标记点坐标过近（沿用源工程坐标），视觉上有轻微压叠。
- 桌面端的宽屏适配是「布局铺满 + 字号固定密度」，不是逐像素还原小程序版式；移动端才是 1:1。
